# 創作與 AI 專案儀表板

## Cover
設計規格與開發順序

靜態 HTML 初版提案

## Slide 1
目前要解決的執行問題

- 多個創作與 AI 方向同時存在，容易分散注意力
- 專案、行動、進度與成果缺少清楚層級
- 需要快速瀏覽、快速更新，而不是複雜的管理系統

## Slide 2
初版系統的核心原則

- 所有想法可以保存，但不必同時執行
- 同時間維持一個主要專案，加上最多兩個副專案
- 每個專案都必須有目標成果、下一步與檢討日期
- 每週要留下可見、可回顧的成果

## Slide 3
五個主要區塊形成工作循環

- 首頁總覽：確認本週焦點與今天的下一步
- 進行中專案：管理目前真正投入時間的專案
- 專案池：保存尚未啟動的構想
- 本週行動：把專案拆成可在工作時段完成的任務
- 成果紀錄：累積已完成、已發布與可展示的產出

## Slide 4
進度追蹤表是核心資料層

- 一筆紀錄代表一次完成、決策、阻礙或方向更新
- 必須記錄完成事項、實際產出、進度變化與下一步
- 進度不只看百分比，也看產出數量、驗證結果與執行週數
- 讓未來的自己能快速理解專案脈絡

## Slide 5
靜態 HTML 的技術方案

- 單頁 HTML 介面，使用 CSS 與原生 JavaScript
- 使用 localStorage 保存瀏覽器中的專案資料
- 使用 JSON 匯出與匯入完成備份與還原
- 初版不加入登入、資料庫、雲端同步與 AI 自動化

## Slide 6
資料模型與頁面關係

- 專案表：儲存所有方向、專案與狀態
- 行動表：儲存本週與近期任務
- 進度追蹤表：儲存每次更新的時間軸
- 成果表：儲存作品、連結、數據與學習
- 五個頁面是資料表的不同視圖，不重複建立資料

## Slide 7
開發順序：先跑通核心循環

- 第一步：完成五區塊導覽與首頁版面
- 第二步：完成專案、行動、進度與成果的新增與編輯
- 第三步：加入 localStorage 自動保存
- 第四步：加入搜尋、狀態篩選與首頁摘要
- 第五步：加入 JSON 匯入／匯出與響應式調整

## Slide 8
30 天驗證與後續擴充

- 第 1 週：輸入所有想法，選定一主兩副
- 第 2 週：完成第一個可公開或可測試版本
- 第 3 週：持續產出並記錄回饋與阻礙
- 第 4 週：決定專案繼續、調整、暫停或結束
- 穩定使用後，再考慮雲端同步、AI 任務拆解與自動分析

## Slide 9
初版完成判準

- 一分鐘內找到目前主要專案
- 清楚知道本週要完成的成果
- 能快速新增或更新下一步行動
- 每次重要進展都能留下紀錄
- 每週能匯出備份並完成一次檢視
